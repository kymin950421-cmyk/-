# 아이랑 성남
성남시 아동수당 가맹점을 업종·구·검색어로 살펴보는 반응형 웹사이트입니다. Node.js 24 이상에서 실행합니다. 지도에는 Leaflet 1.9.4와 Leaflet.markercluster 1.5.3을 사용합니다.

```sh
npm ci --cache /tmp/sn-npm-cache
npm start
npm test
```
기본 포트 3000, PORT로 변경 가능. 환경의 HTTPS 프록시를 사용하도록 Node의 `--use-env-proxy`를 활성화합니다. TLS 검증을 유지합니다.

## 실제 데이터 연동
- 사이트: https://sn-child-pay.com/
- 데이터 출처: https://github.com/whlee0525/sn-child-pay
- 기본 피드: https://raw.githubusercontent.com/whlee0525/sn-child-pay/main/public/data/all.json
- 확인한 저장소 HEAD: `2d5b6fd40669b99eadc865b238a4ceadde568d54`
- 원본 기준: **2025년 6월**, 제공처 README 설명 기준. 제공처는 매년 신규 데이터를 확인할 예정이라고 안내합니다. 최신 결제 가능 여부를 보장하지 않습니다.

사이트 자체는 환경 프록시에서 차단되지만 README가 사이트 주소를 명시한 공개 GitHub 저장소와 JSON은 조회가 가능합니다. 기본 서버는 GitHub JSON을 시작 시 및 15분마다 확인합니다. 브라우저는 60초마다 서버 상태를 조회합니다. 이는 원본 변경을 주기적으로 수신하는 방식이며 신한카드의 실시간 조회 연동이 아닙니다. 마지막 수신 시각은 원본 갱신 시각이 아닙니다.

확인 당시 원본은 29,482건입니다. 주소에 성남시와 구가 명시된 29,477건을 변환하며 구를 확정하지 못한 5건은 제외합니다. 고유 ID, 필수 필드, 중복과 지역을 검증하고 원본 업종도 보존합니다. 업종을 큰 범주로 분류하며 미분류 업종은 기타로 표시합니다. 60건 단위 페이지로 결과를 표시합니다.

정상 수신 데이터는 `.local/merchants.json`에 원자적으로 저장합니다. 실패 시 마지막 정상 데이터를 유지하고 오류를 표시합니다. 첫 수신 전 정상 캐시가 없으면 가상 예시 6건을 명확히 표시합니다. 다른 피드의 캐시는 재사용하지 않습니다.

## 환경 변수
- MERCHANT_FEED_URL: 기본 GitHub 피드를 대체하는 HTTPS JSON 피드. 아래 정규 형식이 필요합니다. 인증정보를 URL에 넣지 마세요.
- MERCHANT_SOURCE_NAME / MERCHANT_SOURCE_PAGE: 대체 제공처 이름과 HTTPS 출처 페이지
- REFRESH_SECONDS: 기본 900초, 최소 60초
- PORT: 기본 3000

대체 피드 형식:
```json
[{"id":"unique-id","name":"매장명","category":"도서·문구","district":"분당구","address":"성남시 분당구 상세주소"}]
```

## 범위와 출처
원본 프로젝트 코드를 복제하지 않고 공개 데이터 필드에 맞춘 어댑터를 구현했습니다. 출처 링크와 원본 기준일을 화면에 표시합니다. 확인한 저장소 루트에서 LICENSE 파일은 발견하지 못했습니다. 공개 서비스의 재배포 조건은 원저작자에게 확인하는 것이 좋습니다. 공식 신한카드 조회 연동, 매장별 현재 사용 가능 여부, 공개 배포는 검증되지 않았습니다.


## 지도와 위치
원본의 `l: [위도, 경도]` 필드를 검증해 보존합니다. 비정상 좌표 또는 넓은 성남시 주변 범위(위도 37.2~37.6, 경도 126.9~127.4)를 벗어난 좌표는 지도에서만 제외합니다. 이는 출입구 정확도나 시 경계 내 위치의 검증을 의미하지 않습니다. 확인 당시 목록 29,477건 중 29,476건이 지도에 표시되며 좌표 없는 1건도 목록에서는 찾을 수 있습니다.

- 지도 숫자는 화면상 가까운 매장들을 묶은 수이며 행정구역별 합계와는 다릅니다. 클릭하거나 확대하면 분해되고, 최대 확대에서 겹친 매장은 펼쳐집니다.
- 상단 구별 합계는 주소의 구를 기준으로 집계하며 지도 좌표 없는 매장도 포함합니다. 현재 적용된 검색·업종·음식 필터가 반영됩니다.
- 지도 안 매장 수, 필터 결과 전체 위치 보기, 개별 팝업, 카드에서 지도 이동을 지원합니다.
- OpenStreetMap 도로 타일은 외부 네트워크 접근이 필요합니다. 환경에서 `tile.openstreetmap.org` 접근이 차단된 상태이며, 허용 도메인 초안을 저장했습니다. 현재는 실제 도로·건물 배경 확인이 제한됩니다. 실패 안내와 함께 로컬 구 경계 및 매장 좌표가 유지됩니다. 도로 타일을 대량 수집하거나 오프라인 저장하지 않습니다.
- 로컬 참고 경계: 통계청 2013 시군구 단순화 GeoJSON의 성남시 3개 구만 추출. 출처 https://github.com/southkorea/southkorea-maps (kostat/2013/json/skorea_municipalities_geo_simple.json). 최신 법정 경계가 아니며 지도와 문서에 출처·연도를 명시합니다.

## 음식점 세부 필터
음식점 선택 시 한식·일식·중식·양식·피자·치킨·돈까스·분식·카페/디저트·패스트푸드·주점·기타 음식점 필터가 표시됩니다. 지역·검색어와 결합하며 지도와 목록에 동일하게 적용합니다.

원본 업종만으로 구별되지 않는 항목은 매장명 키워드와 일부 체인명으로 추정하며 카드와 팝업에 `매장명 추정`을 표시합니다. 예: 스시→일식, 삼겹살→한식, 피자→피자, 치킨→치킨, 돈가스/돈까스/돈카츠→돈까스. 피자와 치킨을 함께 명시한 매장은 두 필터에 모두 포함되므로 세부 카테고리 합계는 전체 매장 수보다 클 수 있습니다. 원본 업종은 별도로 유지합니다. 메뉴를 검증한 분류가 아니므로 이름만으로 확인되지 않는 매장은 기타 음식점으로 남습니다.

## 카카오 지도 연결 (설정 대기)
화면을 왼쪽 검색/필터/목록, 오른쪽 큰 지도 구조로 변경했습니다. 모바일은 지도와 검색 영역을 위아래로 배치합니다. 카카오 SDK 연결 코드는 준비했으나 앱 키가 없어 실제 도로 타일·인증·클러스터 동작은 아직 검증하지 못했습니다.

1. https://developers.kakao.com/ 에서 로그인하고 내 애플리케이션에서 앱을 생성합니다.
2. 앱의 플랫폼 설정에서 Web을 추가하고 **실제로 접속할 사이트 origin(프로토콜+도메인+필요한 포트)** 을 등록합니다. 공개 배포 주소는 아직 정해지지 않았습니다. 원본 사이트 도메인을 본인 사이트 도메인 대신 등록하지 않습니다.
3. 제품의 카카오맵 사용 설정이 있으면 활성화합니다. 콘솔 메뉴 명칭은 변경될 수 있으므로 https://apis.map.kakao.com/web/guide/ 도 확인합니다.
4. 앱의 **JavaScript 키**를 환경 설정의 `KAKAO_MAP_JAVASCRIPT_KEY`에 등록한 뒤 서버를 재시작합니다. REST API 키나 Admin 키가 아닙니다. 이 브라우저용 키는 `/map-config.js`로 클라이언트에 전달되므로 허용 사이트 도메인 제한이 필요합니다. `.env` 파일을 자동으로 읽지는 않습니다.
5. 실제 사이트에서 SDK 인증, 도로/건물 표시, 지도 확대, 개별 매장, 겹친 좌표 매장 선택, 필터를 확인합니다.

카카오 키가 없으면 연결 대기 안내와 기존 참고 지도만 표시합니다. 카카오 SDK 연결에 실패하면 오류를 표시하며 도로 지도를 표시했다고 주장하지 않습니다. 필요한 네트워크 도메인: dapi.kakao.com 및 SDK의 Daum/Kakao CDN. 기존 OpenStreetMap fallback의 타일 차단 상태와 별개의 요구 사항입니다.

### 현재 카카오 연결 진단
앱 키가 실행 환경에 주입됐으며, 개발 테스트 origin 등록 및 카카오맵 활성화 후 SDK 요청이 HTTP 200을 반환하는 것을 확인했습니다. 런타임 키 값은 파일에 저장하지 않습니다. 로컬 HTTP 개발 환경에서 SDK가 생성하는 CDN 이미지 URL은 HTTPS로 정규화합니다. CSP는 허용된 카카오 스크립트 출처를 제한하면서 SDK의 동적 실행을 위해 `unsafe-eval`을 허용하며, 공개 배포는 HTTPS를 사용해야 합니다.

클라우드 테스트 Chromium은 환경 프록시 CA를 신뢰하지 않아 직접 SDK 요청 시 인증서 오류가 발생합니다. 브라우저 기능 검증은 해당 카카오 리소스를 환경 CA를 신뢰하는 Node fetch로 TLS 검증한 뒤 브라우저에 전달하는 테스트 전용 경로를 사용합니다. 애플리케이션에 인증서 검증 해제나 프록시를 추가하지 않았습니다. 일반 사용자 브라우저 및 공개 배포 도메인에서의 검증은 별도로 필요합니다.
